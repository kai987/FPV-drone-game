# 地图加载优化与测量

2026-10-04，本次优化保持首次进入时全部三张地图就绪后才能开始飞行。地图内容、纹理尺寸、远景全景和昼夜模式保持原有配置。

## 实现

- 根据同一个 WebGL renderer 的纹理能力和画布尺寸选择一份远景图。提前下载、解码四张实际需要的图片，与 WASM 加载和场景构建重叠。纹理直接使用已解码的 Image，不重复请求或解码。
- 三张地图的 CPU 场景逐帧创建。工厂、海港可以在山谷贴图下载期间进行 GPU 预热。共享的相机、无人机和 renderer 始终通过串行队列使用。
- 三张地图均完成日间、夜间预热后才开放起飞和地图选择。复用一个 256×144 预热 RenderTarget；切换继续复用已经准备好的地图。
- 单个挂载取消只中止自己的资源消费者；共享图片和 WASM 可供 StrictMode 的下一次挂载复用。失败图片移出缓存以便下次重试。正在编译的 WebGL 资源在编译结束后释放。
- 树木使用无损 WebP，草地、岩石使用高质量 WebP，保持原尺寸。三张资源合计减少 1,507,216 字节（31.25%）；两版全景文件均未修改。具体质量、哈希和重新编码方法见 [素材说明](asset-licenses.md)。解码后的纹理内存大小没有因此减少。

## 对比结果

在同一台 macOS 设备、同一内嵌浏览器、1280×720 视口、devicePixelRatio=2 下，各执行三次生产构建冷加载。测试 HTTP 服务器对所有本地资源合计限速 **10 Mbps**，响应使用 `Cache-Control: no-store`。浏览器字体和 GPU 驱动缓存未清除，前后采用相同设置；未模拟广域网络延迟。两版都选择 7096×3548 全景。

计时从导航开始，到三张地图实际准备完成、第一帧绘制且“开始飞行”按钮可用后的下一次 animation frame。优化前为 Git `62450333fb213aa24209bd97f843b7731ccba4de` 的构建。

| 版本 | 第一次 | 第二次 | 第三次 | 中位数 |
|---|---:|---:|---:|---:|
| 优化前 | 9,562.0 ms | 9,775.4 ms | 9,545.4 ms | 9,562.0 ms |
| 优化后 | 8,118.8 ms | 8,023.6 ms | 7,933.0 ms | 8,023.6 ms |

该条件下中位数减少 **1,538.4 ms（16.1%）**。这是本地限速测量，不能视作每种设备、网络或线上托管的固定提升比例。三个优化贴图的压缩比例也不代表整站加载加速比例。

浏览器资源记录确认四张图片各只请求一次，未下载另一份全景。优化后第二次测量中，工厂和海港 GPU 准备在初始化约 1.20～1.81 秒完成，山谷图片约 5.66 秒才全部就绪，确认等待时间实际发生了重叠。

## 后续诊断

游戏 canvas 的 `data-loading-metrics` 提供 JSON：`total` 和 `phases`，单位毫秒。`phases` 包含 renderer、WASM 可用时间、全部图片下载/解码、每图 CPU 创建、GPU 准备，以及日夜 shader 编译和首次上传。各阶段可能重叠，因此不能简单相加。

这些阶段的起点是 App 进入加载 effect，**不包含网页入口 bundle 的下载**。`data-initialization-ms` 是同一个初始化总计。比较完整首屏加载速度时仍需使用相同的导航起点和“三张地图就绪且可起飞”终点。

验证：39 项 Rust 测试、183 项 Node 测试、TypeScript 检查和生产构建通过；浏览器检查三图切换、夜间、飞行/投弹、手机布局和控制台错误。
