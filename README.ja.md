# AEROFLOW · FPV Drone Game

[中文](./README.md) | **日本語** | [English](./README.en.md)

ブラウザーで遊べる、ドローンの飛行と爆弾投下練習のゲームです。追尾、真上からの照準、一人称の視点に対応しています。React、TypeScript、Vite、Three.jsが画面と3D描画を担当し、RustをWebAssemblyにコンパイルして、飛行、風、地理情報の照会、投下物、シーンとアニメーションの一括数値計算を実行します。アカウント、バックエンド、有料APIは不要です。

オンラインで遊ぶ：[GitHub Pages](https://kai987.github.io/FPV-drone-game/) · [Sites](https://aeroflow-fpv-drone-game.huamengdiqidiguo.chatgpt.site/)

## ゲームの機能

- 外形、色、操縦応答が異なる6種類の架空FPVドローン。格納庫のサムネイル、回転できる大きなプレビュー、飛行中の機体は同じ3Dモデルを使います。ハードウェア設定とゲーム内の飛行性能を確認できます。
- 独立した3つのマップ。各マップに8個のチェックポイントリング、5個の投下練習標的、対応するミニマップがあります。タイムチャレンジと自由飛行、アシストとスポーツの操縦モードを選べます。
- 無風、微風、中程度、強風の4段階と、8方向の基準風向。離陸時は基準の方向から吹き、その後は実際の風向が時間とともに滑らかに変化します。風速も時間、位置、高度に応じて変化します。向かい風、追い風、横風が実際の対地速度と軌道に影響し、計器は風が来る方向の角度、ミニマップ横のコンパスは吹いていく方向を表示します。一時停止中は風も止まります。
- 爆弾6発、自動補充、陸上の煙や破片、水上の飛沫や波紋。各標的への初回命中で100点を獲得します。
- 昼夜切り替え、機体のサーチライト、明かりのついた窓、街灯、港の灯台。モーター、リング通過、投下の効果音は任意で有効にでき、初期状態はミュートです。
- ドラッグとズームに対応したミニマップ、リアルタイム計器、一時停止と再スタート、全画面表示、スマートフォンのマルチタッチ操作。
- ヘッダーの選択欄で **中文 / 日本語 / English** を即座に切り替えられます。初期言語は中国語で、`zh / ja / en`をlocalStorageの`aeroflow-language`に保存します。切り替えても飛行位置と進行状況、マップ、弾数、風、ミニマップの表示範囲、既存の3Dレンダラーは維持されます。ローカルストレージが使えなくても、言語切り替えと飛行は可能です。

どちらの操縦モードも無風時には自動でホバリングします。風があると流されるため、修正操作が必要です。スポーツは速度、慣性、傾きの反応が大きくなります。遊びやすさを重視したゲームの飛行モデルであり、専門的なAcro/Rate、重力を含む飛行、実際の空力のシミュレーターではありません。

## 3つのマップ

| マップ | 飛行可能な範囲 | 面積 | 景観 |
| --- | --- | --- | --- |
| 松林の谷 · PINE VALLEY | 3.6 × 3.6 km | 12.96 km²、画面では約13 km² | 起伏のある地形、松林、草原、川、翡翠湖、松影湖 |
| 工業工場 · IRON WORKS | 7.2 × 7.2 km | 51.84 km²、画面では約52 km² | 工業道路、外周の生産地区、タンク、煙突、配管、物流ヤード |
| 港湾 · SEA PORT | 7.2 × 7.2 km | 51.84 km²、画面では約52 km² | 沿岸倉庫、コンテナ埠頭、ガントリークレーン、貨物船、広い海 |

全マップの高度上限は450mです。工場と港は元の約4倍の面積に拡張し、出発地点と練習コースは維持しています。区域や施設を追加して広げており、建物全体を拡大したものではありません。

- **谷**：田舎の小屋3軒、木橋1本、歩いたり草を食べたりする牛と羊、川と湖を泳ぐ魚群。水面には複数スケールの波、川筋に沿って流れるテクスチャ、浅瀬の色の変化、空と遠山の映り込みがあります。岩には鉱物の粒、亀裂、苔の模様があり、岸沿いには低木と砂利を配置しています。
- **工場**：工場棟190棟、タンク41基、煙突15本、トラック40台、配管30区間、コンテナ1023個。中心街区には工場棟101棟を配置しています。高架構造の下を通過したり、支持面のある屋根に着陸したりできます。
- **港**：倉庫125棟、埠頭9基、ガントリークレーン9基、トラック27台、貨物船4隻、防波堤2本、コンテナ2932個。中心街区には倉庫54棟を配置しています。追加した6つの埠頭はそれぞれ長さ960mです。海面には波、反射、岸辺の泡があり、夜間の灯台には回転する光があります。
- **道路**：工場と港にはそれぞれ21か所の十字路があり、全ての交差点の4方向に横断歩道と停止線があります。道路、ミニマップ、衝突判定はメートル単位の共通配置を使い、地上の物体は車道と横断歩道を避けています。
- **切り替え**：初回表示時に3マップのシーン、テクスチャ、Rustサービス、昼夜のシェーダーを準備し、マップごとの進捗を表示します。全ての準備が完了してから飛行できます。切り替えはキャッシュを再利用し、選んだマップの出発地点へ戻って、コース、時間、弾数、得点をリセットします。機体、ゲームと操縦のモード、風、昼夜、音、言語、視点は維持します。

## 6種類のドローン

| ゲーム機体 | フレームと色 | アシスト / スポーツの速度上限 |
| --- | --- | --- |
| CINE | 小型ダクトガード、オレンジ | 51.8 / 88.1 km/h |
| FLOW | バランスの取れた標準Xフレーム、緑 | 72.0 / 122.4 km/h |
| RACE | 細い機体のレース用フレーム、赤 | 97.2 / 165.2 km/h |
| RANGE | 長いアーム、大型バッテリー、高いアンテナ、青 | 64.8 / 110.2 km/h |
| VECTOR | 低いフェアリングと対称の高速Xフレーム、水色 | 152.9 / 260.0 km/h |
| FALCON | 軸方向に長い中央ポッドと4つの平行なモーターポッド、金 | 211.8 / 360.0 km/h |

上記は通常操作・無風時の共通飛行設定から計算したゲーム内の制限速度です。実際の対地速度は風、旋回、加速、減速で変わります。**全ての機体は架空のゲーム設定です。ハードウェアと飛行時間も架空の設定で、バッテリー消費は再現せず、実製品の測定値や世界記録を表すものではありません。**

格納庫の大きなプレビューはドラッグで回転、ホイールやピンチでズームでき、リセットで元の表示に戻せます。飛行中に格納庫を開くと一時停止します。機体を変更する場合は「出発地点に戻って適用」で出発地点へ戻る必要があります。FALCONはホバリング時に主軸が直立し、前進すると進行方向へ傾きます。

VECTORは[DRL RacerXの2017年記録の記事](https://www.guinnessworldrecords.com/news/commercial/2017/7/the-drone-racing-league-builds-the-worlds-fastest-racing-drone-482701)、FALCONは[AirShaperのPeregreen V4事例](https://airshaper.com/cases/peregreen-v4-fastest-drone)を参考にしています。格納庫では原型の資料とゲーム内性能を分けて表示し、モデルの形はゲーム向けにアレンジしています。

飛行中に3D画面をクリックするとマウス視点を使えます。Escでマウスを解放して一時停止します。タブを切り替えたりウィンドウのフォーカスが外れたりしたときも自動で停止します。スマートフォンでは離陸後に移動、旋回、高度のボタンを表示し、同時に複数を押せます。入力欄、選択欄、モーダル画面では飛行ショートカットを分離し、画面操作による意図しない移動や投下を防ぎます。

### 飛行・風・投下のヒント

- **タイムチャレンジ**：光るリングを順番に正面から通過します。衝突で減速し、3秒が加算されます。継続して接触している場合はペナルティのクールダウンがあります。**自由飛行**ではリング通過の条件や衝突による時間ペナルティはありません。
- 飛行中と一時停止中はゲームと操縦のモードを変更できません。変更するには出発地点へ戻ります。風はいつでも調整でき、設定を開くと一時停止します。適用後も位置、時間、弾数を維持し、手動で再開するまで待機します。
- 初期設定は北西を基準とする微風で、少し流されます。無風を選び、Wを押して最初の2つのリングを練習できます。風の名前とリアルタイムの角度は吹いてくる方向を示し、北風は北から南へ吹きます。コンパスの矢印は吹いていく方向です。実際の風向は自動で滑らかに変化するため、角度と矢印を見て逆方向へ修正してください。一時停止中は風向と風速が変わらず、再スタートすると基準方向から始まります。アシストでは流されにくく、スポーツでは積極的な修正が必要です。
- 出発地点の真下に練習標的があります。離陸後、Vで真上照準へ切り替え、Bで投下します。爆弾は機体の速度を引き継ぎ、照準は機体の真下を示します。予測着弾点ではありません。
- 6発を使い切ると3秒で補充します。5個の標的への初回命中はそれぞれ100点です。投下の得点とリングの時間は独立し、両ゲームモードで投下できます。一時停止すると爆弾、爆発、補充時間も止まり、再スタートで弾数、標的、得点を初期化します。
- 谷のミニマップにある水色の魚アイコンが魚群の位置です。出発地点の東側の川の曲がり、木橋の下流、湖へ近づき、水面の約2–8m上でホバリングして真上視点にすると観察しやすくなります。高空や水平の視点では反射に隠れることがあります。
- 水面に接触すると機体を安定させます。カメラ、機体、爆弾は共通の地面/水面照会を使います。自由飛行では川沿いに2つの湖を探索したり、都市マップ全域を巡航したりできます。

自己ベストは現在のブラウザーのlocalStorageに、マップ、機体、操縦モード、風の強さ、基準風向ごとに保存します。無風では方向を区別しません。風向の変化と建物の密集化に対応した新記録は別に保存し、旧来の風あり記録と都市マップの記録は混在させません。谷の無風条件では同じ機体・操縦モードの旧記録を引き続き読み込み、元の記録も残します。飛行途中で風設定を手動変更した回は自己ベストに記録しませんが、自動の風向変化は記録対象のままです。再スタートすれば再び記録できます。保存が禁止されていても飛行できます。

## ローカル実行

開発には **Node.js 22.18以上（24推奨）**、npm、rustupで管理するRust/Cargoが必要です。[rust-toolchain.toml](./rust-toolchain.toml)で **Rust 1.93.0** と **`wasm32-unknown-unknown`** ターゲットを固定しており、初回はrustupが設定に従ってツールチェーンを準備します。

プレイヤーには **WebGL 2、WebAssembly、ハードウェアアクセラレーション** 対応のブラウザーだけが必要で、Node.jsやRustのインストールは不要です。

```sh
npm ci
npm run dev
```

ターミナルに表示されたURLを開きます。通常は [http://127.0.0.1:5173/](http://127.0.0.1:5173/) です。

```sh
npm run build:wasm # Rustを個別にビルドしてWASMを更新
npm test           # WASM生成、CargoネイティブテストとNodeテスト
npm run check      # npm testの後にTypeScriptチェック
npm run build      # WASM生成、TypeScriptチェック、dist/を生成
npm run preview    # 既存dist/のプレビュー。通常http://127.0.0.1:4173/
```

開発、テスト、チェック、本番ビルドでは先にWASMを生成します。開発サーバーはRustのソース変更を監視しないため、変更後は`npm run build:wasm`を実行するか、`npm run dev`を再起動します。`src/game/generated/flight_core.wasm`、Cargoの`target/`、`node_modules/`、`dist/`はGitで無視するビルド・依存関係の生成物で、新規チェックアウトでも上記コマンドで再生成できます。

ゲーム素材はリポジトリに含まれ、実行時に生成AIを呼び出しません。フォントはGoogle Fontsから読み込む場合があり、オフラインなどではシステムフォントへ戻ります。アカウント、データベース、有料API、サーバー秘密情報への依存はありません。

## ビルドと公開

`npm run build`が生成する **`dist/`が完全な静的サイト** です。HTML、JavaScript、CSS、WASM、画像素材を含むこのディレクトリを静的ホストに公開します。ソースだけの公開やソースHTMLを直接開く方法では本番ゲームは動きません。Viteの`base: './'`により、GitHub Pagesの`/FPV-drone-game/`を含むサブディレクトリに対応します。WASMローダーはストリーミングコンパイルを使い、ホストのMIMEタイプが適切でない場合は同じバイト列を通常の方法でコンパイルします。

GitHub Pagesの設定：

1. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
2. `main`へプッシュします。[pages.yml](./.github/workflows/pages.yml)がNode.js 24とRust 1.93.0のWASMターゲットを用意し、`npm ci`、`npm run check`、`npm run build`を実行します。
3. `dist/`をPages artifactとしてアップロードし、`github-pages`環境にデプロイします。チェックやビルドが失敗すると公開しません。
4. `build`と`deploy`の両方の成功を確認し、[Pagesのゲーム](https://kai987.github.io/FPV-drone-game/)で読み込みと離陸を確認します。

**Actions → Deploy game to GitHub Pages → Run workflow** で`main`を選び、手動で再公開することもできます。他のブランチは公開せず、プッシュとPRは独立した[ci.yml](./.github/workflows/ci.yml)で検証します。`dist/`と生成WASMはGitにコミットしません。通常のCI成功だけではデプロイ完了を意味しません。参考：[GitHubのカスタムPagesワークフロー](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## Rustと描画の構成

- **Rust/WASM**：位置、速度、姿勢、風の計算。地形、河湖、橋、屋根、甲板、障害物の空間グリッド照会。投下の弾道、初回命中、得点、補充。森林、岩、低木、地形色、水面テクスチャの生成。魚、家畜、爆発のアニメーションを一括計算します。
- **TypeScript/Three.js**：入力、共通マップ・機体設定、リングと計時、音、言語と画面、ジオメトリ、マテリアル、カメラ、水面・炎・植生のGPUシェーダー、3D描画を担当します。

1ゲームで1つのWASMインスタンスとWebGLコンテキストを共有します。各マップは独立した世界、飛行、武器のサービスを持ち、各サービスは専用バッファーとライフサイクルを管理します。メモリー拡張後はアダプターがビューを取得し直します。飛行フレームごとに1回の`simulate_world_tick`で飛行と風を計算し、武器とアニメーションはそれぞれ一括更新してThree.jsへ結果をコピーします。飛行と爆弾は同じRust世界を直接照会します。

マップは共通設定と手続き型モデルから生成するシーンで、完成した3DマップファイルをRust内に梱包したものではありません。都市の建物、回転したコンテナ、埠頭、防波堤、船体は共通のメートル単位の配置で描画、ミニマップ、Rust衝突判定を駆動します。9埠頭と2防波堤をRustの陸地の和集合へ一度アップロードし、陸水判定と支持面の高さを一致させます。

初回読み込みではデコード済み画像を再利用し、テクスチャのダウンロードとシーン準備を重ねて実行します。3マップの昼夜GPUリソースは順次コンパイルして事前描画します。木はインスタンス化した貼り板、都市の基本構造は材質ごとのインスタンスバッチを使い、細部は600mの空間ブロックに分けて、包囲球に450mの距離余裕を加えて表示を判定します。夜間の街灯は固定8灯のプールを使います。ゲームを離れる際に全マップと描画リソースを解放します。

旧TypeScriptの数式や固定した旧シーン・爆発方程式は独立したテスト参照として残しています。本番ではRustサービスを使い、読み込み失敗時は通知を表示し、黙ってJS物理へ切り替えることはありません。WASMは引き続きメインスレッドで同期実行し、Workerは使用しません。Rust移行やマップ最適化によるFPS向上は主張しておらず、性能変化は別途測定が必要です。

## 検証

`npm run check`はCargoネイティブテスト、実際のWASMファイルを使うNodeテスト、TypeScriptチェックを実行します。`npm run build`で本番ビルドを検証します。テスト数は機能追加で変わるため、最新の件数は実行結果を参照してください。

6機体、2操縦モード、4段階の風、8方向、30/60/120fpsの数値互換性、通常入力による谷と都市の8リング全コースを検証します。一時停止、不正な時間刻み、境界、橋上・橋下、屋根・甲板、高架と回転物体の衝突、武器ライフサイクル、複数階層の着弾面、記録と言語保存、マップキャッシュ、リソース解放も対象です。シード付きシーン、地形全体の高さと色、水面模様と流向、魚・家畜・爆発の一括アニメーション、拡張マップの道路、泊位、陸水境界、ミニマップの範囲も確認します。

ブラウザー検証では3マップの事前読み込み、マップと機体の変更、昼夜、投下、言語変更、デスクトップとスマートフォンサイズのミニマップ・タッチ操作、画面のはみ出し、コンソールを確認します。ブラウザーの表示サイズでの確認は実機スマートフォンのGPUベンチマークではなく、実ドローンの性能も検証対象には含みません。
