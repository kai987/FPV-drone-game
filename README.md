# AEROFLOW · FPV Drone Game

**中文** | [日本語](./README.ja.md) | [English](./README.en.md)

可直接在浏览器中玩的无人机飞行与投弹练习游戏，支持追尾、俯视瞄准和第一视角。React、TypeScript、Vite 和 Three.js 负责界面与三维画面，Rust 编译为 WebAssembly，运行飞行、风场、地理查询、投弹及场景与动画的批量数值计算。无需账号、后端或付费 API。

在线体验：[GitHub Pages](https://kai987.github.io/FPV-drone-game/) · [Sites](https://aeroflow-fpv-drone-game.huamengdiqidiguo.chatgpt.site/)

## 游戏内容

- 六款具有不同外形、配色与操纵响应的虚构 FPV 无人机。机库的缩略图、可旋转大图和飞行场共用同一三维模型，可查看硬件设定和游戏性能参数。
- 三张独立地图，各有八个检查环、五个投弹靶标及对应小地图；提供计时挑战和自由飞行、辅助和运动两种操控模式。
- 无风、微风、中等风、强风与八个基准来风方向。起飞时使用基准方向，随后实际风向随时间平滑偏转；风速也随时间、位置和高度变化。迎风、顺风与侧风影响实际地速和航迹，仪表实时显示来风度数，小地图旁的罗盘箭头显示风吹向；暂停会冻结风场。
- 六枚炸弹、自动装填、陆地烟尘与碎屑、水面飞溅与涟漪。每个靶标首次命中获得100分。
- 日夜切换、无人机探照灯、亮窗、都市路灯、海港灯塔；可选电机、穿环与投弹音效，默认静音。
- 可拖动和缩放的小地图、实时飞行仪表、暂停与重新起飞、全屏及手机多点触屏操作。
- 页头可立即切换 **中文 / 日本語 / English**。默认中文，语言以 `zh / ja / en` 保存在 localStorage 的 `aeroflow-language` 中。切换保留飞行位置与进度、地图、弹药、风况、小地图视野和现有三维渲染器；本地存储不可用时仍可切换语言和飞行。

两种操控模式在无风时均自动维持悬停；有风时会漂移，需要主动修正。运动模式提供更快速度、更大惯性和倾斜反馈，属于易上手的游戏模型，不是专业 Acro/Rate、重力飞行或真实空气动力学模拟。

## 六款无人机

| 游戏机型 | 机架与配色 | 辅助模式 / 运动模式速度上限 |
| --- | --- | --- |
| CINE | 紧凑涵道护圈，橙色 | 51.8 / 88.1 km/h |
| FLOW | 均衡标准X架，绿色 | 72.0 / 122.4 km/h |
| RACE | 窄机身竞速架，红色 | 97.2 / 165.2 km/h |
| RANGE | 长机臂、大电池与高天线，蓝色 | 64.8 / 110.2 km/h |
| VECTOR | 低矮罩壳、对称高速X架，青色 | 152.9 / 260.0 km/h |
| FALCON | 轴向中央长舱与四个平行电机舱，金色 | 211.8 / 360.0 km/h |

以上是普通操控、无风条件下由共享飞行配置计算的游戏限速；实际地速会受到风、转向和加减速影响。**全部机型均为虚构游戏配置，硬件和续航也属虚构设定，不模拟电池耗电，不代表真实产品实测或世界纪录。**

机库大图支持拖动旋转、滚轮或双指缩放以及复位。飞行途中查看机库会暂停；更换机型需返回起点，界面提供“返回起点并应用”。FALCON悬停时主轴直立，前进时向航向倾转。

VECTOR的灵感来自 [DRL RacerX的2017年纪录报道](https://www.guinnessworldrecords.com/news/commercial/2017/7/the-drone-racing-league-builds-the-worlds-fastest-racing-drone-482701)，FALCON来自 [AirShaper的Peregreen V4项目案例](https://airshaper.com/cases/peregreen-v4-fastest-drone)。机库将原型资料与游戏性能分开显示，模型外形经过游戏改编。

飞行时点击三维画面可启用鼠标视角。Esc释放鼠标并暂停；切换标签页或失去窗口焦点也会自动暂停。手机起飞后在飞行画面上用手势操作：单指按住从低速逐渐加速，约2秒达到当前机型和模式的最大输入；上下拖动控制前后，左右拖动控制平移。第二根手指上下拖动控制升降，左右拖动控制转向，两指可同时操作。松手会撤销对应输入并由飞行物理减速；辅助模式制动更快，有风时仍可能漂移。投弹、风向和小地图移到画面下方的底部面板，小地图的拖动与缩放不会操控无人机。输入框、选择器和模态窗口会隔离飞行快捷键，避免操作界面时意外飞行或投弹。

### 飞行、风况和投弹提示

- **计时挑战**：按顺序从正面穿过亮色环。碰撞减速并增加3秒，持续接触有惩罚冷却。**自由飞行**无需穿环，也没有碰撞计时惩罚。
- 游戏与操控模式在飞行和暂停期间锁定，返回起点后可以切换。风况可随时调整；打开设置会暂停，应用后保留位置、计时和弹药，等待手动继续。
- 默认基准西北微风会造成轻微偏移；选择无风后，按W可练习前两个环。风向名称与实时度数表示来向，北风从北向南；罗盘箭头表示吹向。实际方向会自动平滑变化，留意度数与箭头，适时反向修正。暂停时风向和风速保持不变，重新起飞从基准方向开始。辅助模式减轻风偏，运动模式需要更主动修正。
- 起点正下方有练习靶标。起飞后按V切到俯视瞄准，再按B投弹。炸弹继承无人机速度，准星指向机身下方而非预测落点。
- 六枚炸弹投完后3秒自动补充；五个靶标各首次命中得100分。得分与穿环计时独立，两种游戏模式均可投弹。暂停冻结炸弹、爆炸和装填倒计时；重新起飞恢复弹药、靶标和得分。
- 山谷小地图的浅蓝鱼形标记指示鱼群。靠近起点东侧河湾、木桥下游或湖泊，在水面上方约2–8m悬停并切到俯视更易观察；高空或水平视角会受反光影响。
- 接触水面会稳住机身；相机、无人机与炸弹共用地面/水面查询。自由飞行中可沿河探索两处湖泊，或在都市地图全域范围巡航。

个人最佳保存在当前浏览器的localStorage中，按地图、机型、操控模式、风力和基准来风方向区分；无风成绩忽略方向。动态风向与更密集都市更新后的成绩单独保存，旧有风成绩及旧都市成绩不与新版混用；山谷无风仍可读取同机型、同操控模式的旧成绩，原记录保留。飞行中手动更改风况的这一轮不计入个人最佳，自动风向变化不影响记录资格；重新开始后可正常记录。禁用本地存储仍可飞行。

## 本地运行

开发需要 **Node.js 22.18+（建议24）**、npm，以及由rustup管理的Rust/Cargo。[rust-toolchain.toml](./rust-toolchain.toml)固定 **Rust 1.93.0** 和 **`wasm32-unknown-unknown`** 目标，首次使用时rustup会按配置准备工具链。

玩家只需支持 **WebGL 2、WebAssembly和硬件加速** 的浏览器，不需要安装Node.js或Rust。

```sh
npm ci
npm run dev
```

打开终端给出的地址，默认是 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。

```sh
npm run build:wasm # 单独编译Rust并更新WASM
npm test           # 构建WASM，运行Cargo原生测试与Node测试
npm run check      # npm test，再进行TypeScript检查
npm run build      # 构建WASM、检查TypeScript，生成dist/
npm run preview    # 预览已有dist/，默认http://127.0.0.1:4173/
```

开发、测试、检查和生产构建都会先生成WASM。开发服务器不监听Rust源码；修改Rust后执行`npm run build:wasm`，或重启`npm run dev`。`src/game/generated/flight_core.wasm`、Cargo的`target/`、`node_modules/`和`dist/`均为忽略的构建或依赖产物，全新检出可由上述命令生成。

游戏美术随仓库提供，运行时不调用生成式AI。字体可从Google Fonts加载，离线或不可用时回退到系统字体；没有账号、数据库、付费API或服务器密钥依赖。

## 构建与发布

`npm run build`生成的 **`dist/`是完整静态网站**，包含HTML、JavaScript、CSS、WASM和美术资源。部署到静态主机时发布这个目录；只发布源码或直接打开源码中的HTML不能运行生产游戏。Vite的`base: './'`支持子目录，包括GitHub Pages的`/FPV-drone-game/`。WASM加载器支持流式编译，静态主机MIME类型不合适时会使用相同字节的普通编译方式。

GitHub Pages设置：

1. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
2. 将变更推送到`main`。[pages.yml](./.github/workflows/pages.yml)安装Node.js 24与Rust 1.93.0的WASM目标，执行`npm ci`、`npm run check`和`npm run build`。
3. 工作流上传`dist/`作为Pages artifact，并部署到`github-pages`环境。检查或构建失败时不会发布。
4. 确认`build`和`deploy`均成功，再打开[Pages游戏](https://kai987.github.io/FPV-drone-game/)检查加载和起飞。

也可在 **Actions → Deploy game to GitHub Pages → Run workflow** 选择`main`手动重新发布。其他分支不发布；推送与PR通过独立的[ci.yml](./.github/workflows/ci.yml)进行检查。`dist/`及生成的WASM不提交Git。普通CI成功不等于部署完成。工作流参考：[GitHub自定义Pages工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## Rust与渲染架构

- **Rust/WASM**：飞行位置、速度、姿态与风场；地面、河湖、桥面、屋顶、甲板与障碍空间网格；投弹弹道、首次命中、计分和装填；树林、岩石、灌木、地形颜色与水纹生成；鱼群、牛羊及爆炸粒子的批量动画计算。
- **TypeScript/Three.js**：输入、共享地图与机型配置、穿环和计时、音效、语言与界面，以及几何、材质、相机、GPU水面/烟火/植被着色器和三维渲染。

一个游戏共享一个WASM实例和WebGL上下文。每张地图拥有独立世界、飞行与武器服务；各服务拥有独立缓冲与生命周期，内存增长后适配层重新取得视图。每个固定的1/60秒模拟步通过一次`simulate_world_tick`计算飞行与风场，炸弹、装填、计时和碰撞冷却使用同一个步长。低帧率会补进多个子步，每帧最多15步；超过0.25秒的时间统一丢弃，暂停与恢复不会补算后台时间。Three.js对位置和姿态插值显示，飞行与炸弹直接查询同一Rust世界。

地图是共享配置与程序模型生成的场景，不是作为完整三维地图文件打包进Rust。厂港的建筑、旋转货箱、码头、防波堤和船体由同一米制布局驱动渲染、小地图与Rust碰撞；九座码头和两道防波堤一次上传到Rust陆地并集，保持地面/水域判定和支撑高度一致。

首次加载会重用已解码图像，将纹理下载与场景准备重叠，并依次预编译和预热三张地图的日夜GPU资源。树木使用实例化贴图；都市基础结构按材质批量实例化，细节按600m空间块组织，根据包围球与450m距离余量判断显示，夜间路灯使用固定八盏灯的池。离开游戏时释放全部地图与渲染资源。

原TypeScript数学及冻结的旧场景/爆炸方程保留作独立测试参考，生产使用Rust服务，加载失败显示提示，不悄悄切回JS物理。WASM数值计算仍在主线程同步执行，没有Worker；没有声称Rust迁移或地图优化提高了多少FPS，性能变化需要单独测量。

飞行中自动测量FPS、帧间隔、模拟/场景/渲染提交的CPU耗时和绘制/资源计数。持续低帧时逐档降低渲染像素比例，稳定后谨慎恢复；粗指针设备目标30FPS，其他设备目标60FPS，像素比例不会超过设备DPR或1.75。性能数据约每秒更新一次，位于游戏canvas的`data-performance-metrics`，属于CPU与帧节奏测量，不是GPU执行时间，也不是达到目标帧率的保证。

## 验证

`npm run check`运行Cargo原生测试、读取真实WASM的Node测试及TypeScript检查；`npm run build`验证生产构建。测试数量会随功能增长，以执行结果为准。

覆盖六机型、两操控模式、四档风力、八风向及30/60/120fps的数值兼容；普通操纵输入完成山谷与都市八环航线；检查暂停、无效步长、边界、桥上/桥下、屋顶/甲板、高架与旋转箱体碰撞、武器生命周期、分层落点、成绩与语言存储、地图缓存和资源释放。另验证种子场景、完整地形高度与颜色、水纹/流向、鱼群/牛羊/爆炸批量动画，以及扩大地图的道路、泊位、陆水边界与小地图范围。

浏览器功能验证包括预加载三图、地图与机型切换、昼夜、投弹、语言切换、桌面和手机尺寸的小地图/触屏操作、页面溢出及控制台。浏览器视口验收不等同于实体手机GPU基准；真实无人机性能也不在验证范围内。

## 美术与许可

雪峰、松林山谷和蓝天白云全景由内置Image Gen生成1774×887原图，经Real-ESRGAN四倍超分，提供7096×3548高清WebP及3548×1774手机版，按画面宽度和GPU能力选择其中一版。它是超分增强素材，不是原生7K/8K摄影。天空随相机移动，地平线下树林过渡为雾色，河湖反射共用全景。

透明松树、草地和风化岩石纹理也是生成素材，已离线转换为WebP；松树RGBA逐像素保留，草地与岩石保持原尺寸，高清全景没有被压缩优化替换。编码工具仅离线使用，不属于玩家或构建依赖。素材来源、处理命令、许可说明与SHA256详见[素材记录](./docs/asset-licenses.md)及[设计文档](./docs/design.md)。

HUD与控件使用HTML/SVG，图标来自Lucide。字体使用Manrope/Noto Sans及系统回退。源码采用仓库的[MIT License](./LICENSE)；素材来源与第三方工具许可按素材记录分别说明，不将软件许可冒充生成图或模型权重的许可。
